# agent_run() calls the Claude Code CLI read-only, on the owner's subscription

`agent_run(prompt, schema, workdir = ".", timeout = 600)` runs `claude -p` once through processx and returns the schema-validated JSON result as an R object (#75). It runs read-only and isolated, and its auth is the owner's Claude subscription (OAuth), so `--bare`, which never reads OAuth, is out. Spike 1 follows hal 0.1.4's ideas (a fake CLI that speaks the real wire format, processx tree cleanup) but avoids its defaults: `bypassPermissions` with no repo isolation, swallowed parse errors, an inactivity timer instead of a wall-clock bound, the prompt in argv, and no `--json-schema`.

## Decisions

- **Fixed argv; the prompt goes on stdin.** The argv is exactly `-p --output-format json --json-schema <schema> --safe-mode --restricted --strict-mcp-config --tools Read,Glob,Grep --disallowedTools mcp__* <secret deny rules> --permission-mode dontAsk --permission-prompts none --disable-slash-commands --no-session-persistence --model sonnet --max-turns 20 --max-budget-usd 1`. The prompt never goes in argv: argv shows up in `ps`, and Windows caps the command line at about 32k characters. `bypassPermissions`, `--dangerously-skip-permissions`, `acceptEdits`, `--allowedTools`, `Bash`, `Edit`, `Write`, `WebFetch` and `--bare` never appear, and a test asserts it. The model, turn cap and budget cap are constants, not arguments, until a caller needs to pass them.
- **No repo or user customisations.** `--safe-mode` plus `--restricted` plus `--strict-mcp-config`. Without `--bare`, a `-p` session would otherwise run a project's hooks and MCP servers, even in a folder nobody has trusted. `--safe-mode` is documented as a troubleshooting flag, so its scope may change. `--restricted` alone still blocks settings, hooks and Bash.
- **API and provider credentials are removed from the child environment**, so billing always goes through the subscription. The removed variables are `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`, `ANTHROPIC_CUSTOM_HEADERS` (it can carry an Authorization header), `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`, `CLAUDE_CODE_USE_FOUNDRY`, `CLAUDE_CODE_USE_MANTLE` and `CLAUDE_CODE_USE_ANTHROPIC_AWS`, the names in the env-vars docs on 2026-10-21. `CLAUDE_CODE_OAUTH_TOKEN` (`claude setup-token`) is the subscription and passes through. An `apiKeyHelper` in settings files is ignored under `--restricted`. fmisc never reads, stores or passes OAuth tokens. The function is for attended, low-volume use and does no batch runs over rows. Under the Consumer Terms that is the "ordinary, individual usage" the Claude Code docs allow. Heavy scripted use is a grey zone.
- **`schema` is a JSON Schema string**, not an R list (`jsonlite::toJSON(auto_unbox = TRUE)` silently turns `required = "a"` into a scalar) and not yet an ellmer type. The owner prefers `ellmer::type_object()` and friends, but CRAN ellmer 0.5.0 (2026-09-04) exports no type-to-JSON-Schema function. Its only converter is the internal S7 generic `as_json(provider, type)` ([R/provider.R](https://github.com/tidyverse/ellmer/blob/v0.5.0/R/provider.R), [R/as-json.R](https://github.com/tidyverse/ellmer/blob/v0.5.0/R/as-json.R)), which needs a provider object. Its exported `type_from_schema()` converts the other way. fmisc does not call ellmer internals. **Follow-up:** accept ellmer types once ellmer exports a public converter, with ellmer in Suggests.
- **Secret files are denied by fixed Read rules**, passed through `--disallowedTools`: `Read(.env*)`, `Read(.Renviron*)`, `Read(.netrc)`, `Read(.git-credentials)`, `Read(*.pem)`, `Read(*.key)`, `Read(id_rsa*)`, `Read(id_dsa*)`, `Read(id_ecdsa*)`, `Read(id_ed25519*)` and `Read(.ssh/**)`. The rules use gitignore syntax, so a pattern without a slash matches at any depth. Claude Code checks file access only against Read and Edit rules and applies Read rules best-effort to Glob and Grep, so no Glob or Grep rules are passed: the CLI would accept them but never consult them. SSH keys are listed by key type rather than as `id_*`, which would also hide files such as `id_utils.R`. This is **defense in depth, not a sandbox**: it catches the usual file names, not a secret under any other name.
- **`workdir` is read in place, not copied.** `--restricted` confines the file tools to the working directory, and no write tools exist. The temp copy comes with write mode, where it protects the original.
- **`timeout` is total wall-clock time**, enforced by processx `timeout` with `cleanup_tree = TRUE`, so the CLI and its children are killed. Because the call uses `error_on_status = FALSE`, processx reports a timeout as a flag, not an error, so `agent_run()` raises `fmisc_agent_timeout` itself.
- **Errors are classed and never swallowed.** All of them inherit from `fmisc_agent_error`: `_invalid_argument`, `_missing_package`, `_cli_missing`, `_timeout`, `_failed` (non-zero exit, `is_error`, or non-JSON stdout, detected with `jsonlite::validate()` instead of a tryCatch) and `_no_output` (a refusal). Diagnostics such as `exit_status`, `subtype` and `stderr` are condition fields. Messages never carry the prompt, the model's text or file content.
- **Tests run against a fake `claude` on PATH** (`tests/testthat/fixtures/fake-claude.R`, copied and made executable at test time) with recorded-output scenarios. One opt-in smoke test hits the real CLI only when `FMISC_REAL_CLAUDE=true` is set, never on CI or CRAN, because it spends subscription quota. Subprocess tests skip on CRAN and on Windows.

## Consequences

- Apart from the deny-listed names, the agent can **read every file in `workdir`** and send it to the model. Managed policy settings and installed mods still apply. Sanitising untrusted prompt text is the caller's job.
- `--bare` "will become the default for `-p` in a future release" (Claude Code docs). If that ships without an opt-out, subscription-backed `agent_run()` fails with an auth error (`fmisc_agent_failed`). The `auth_error` fake scenario covers this path.
- No Windows support yet, because the npm `.cmd` shim drops stdout under processx. No CLI version gate (the minimum is 2.1.259, for `--permission-prompts`).
- Out of scope for spike 1: write mode (temp copy plus a patch for a separate model-free step to apply), streaming, sessions, R functions as MCP tools, a Codex backend, and batch runs.
